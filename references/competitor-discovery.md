# Competitor discovery · 观

1. Define the object, user task, market/context and constraints. Inspect existing capabilities and baseline before proposing features. Use search intent/device only where relevant.
2. Select enough relevant competitors or exemplars to cover distinct mechanisms (typically 3–6 for a full audit; fewer for a narrow increment). Match user tasks, not brand fame.
3. For each applicable dimension (choose for the object before comparison), identify the strongest **observed** reference, not an assumed universal champion.
4. Prefer live pages and real task flows; collect canonical URLs, observation date, viewport, language, screenshots, and measurable observations. Respect authentication, access restrictions and robots/terms. Do not invent analytics, competitors, prices, rankings, traffic, or screenshots.
5. Inspect your own object with identical tasks and conditions. Treat comparisons without equivalent conditions as qualitative.

Separate evidence levels:
- E1: direct observed workflow, reproducible measurement or code/test.
- E2: documented official product behavior or credible independent report.
- E3: unverified assumption or marketing claim. Requires verification.

Offline observations may use an artifact identifier, date, method and evidence location instead of a URL. The JSON advantage trace requires HTTP(S), so retain non-URL evidence in the narrative without fabricating links.

Deliver: competitors by role, comparison scenarios, strengths/weaknesses, evidence, uncertainty. Search rankings vary by region/time: do not claim competitors are ranked above us unless supported by current SERP/GSC evidence.
